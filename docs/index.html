نصب

از پیشخوان وردپرس

  1. پیشخوان ← افزونه‌ها ← «افزودهٔ جدید» ← «بارگذاری افزونه».
  2. فایل hoosh-seo.zip را انتخاب و «هم‌اکنون بارگذاری کن» را بزنید.
  3. «فعال‌سازی» را بزنید. جدول‌ها در همین مرحله خودکار ساخته می‌شوند.
  4. از منوی «هوش‌سئو» گزینهٔ «باز کردن استودیو» را بزنید؛ استودیو در تب تازه باز می‌شود.
ℹ️
ساختار بسته فایل اصلی افزونه باید یک پوشه زیر ریشهٔ ZIP باشد، نه دو پوشه. ساختار دو-لایه باعث خطای «افزونهٔ معتبر یافت نشد» می‌شود.
hoosh-seo.zip
└── hoosh-seo/
    ├── hoosh-seo.php      ← سربرگ افزونه
    ├── uninstall.php
    ├── readme.txt
    ├── includes/
    ├── assets/
    ├── docs/
    └── languages/

با FTP

پوشهٔ hoosh-seo را در wp-content/plugins/ بفرستید و از فهرست افزونه‌ها فعالش کنید.

⚠️
پوشهٔ .git را ارسال نکنید. یک مخزن گیت با هزاران ریزفایل، هم آپلود را بی‌نهایت طولانی می‌کند و هم در میزبان‌های اشتراکی خطای «ظرفیت inode» می‌دهد.
rsync -a --exclude '.git' --exclude 'node_modules' \
  ./ ./your-site/wp-content/plugins/hoosh-seo/

اتصال هوش مصنوعی

  1. استودیو ← «تنظیمات هوش مصنوعی».
  2. سرویس را انتخاب کنید: OpenAI، Claude، Gemini، DeepSeek، Groq، Mistral، Perplexity، Cohere، Ollama محلی، یا هر سرویس سازگار با OpenAI.
  3. کلید API را وارد و «آزمون» را بزنید.
  4. سقف هزینهٔ ماهانه را تعیین کنید؛ بعد از رسیدن به آن، افزونه خودکار تولید را متوقف می‌کند.
🔒
کلیدها به مرورگر فرستاده نمی‌شوند. استودیو فقط «تنظیم شده / نشده» و یک نسخهٔ ماسک‌شده را می‌بیند؛ کلید واقعی تنها سمت سرور استفاده می‌شود.

استودیو

استودیو یک اپلیکیشن تمام‌صفحهٔ مستقل است، نه یک صفحهٔ پیشخوان: طراحی RTL-first، حالت روشن/تیره/خودکار، سه سطح تراکم، و پالت فرمان با ⌘K یا Ctrl+K.

استودیو با یک نشانی موقت و امضاشده باز می‌شود. اگر «مهلت این نشانی تمام شد» را دیدید، از منوی «هوش‌سئو» در پیشخوان دوباره بازش کنید.

کلید API و داده‌های حساس هرگز در خروجی استودیو چاپ نمی‌شوند.

عیب‌یابی

«افزونهٔ معتبر یافت نشد» یا خطای فاجعه‌بار هنگام فعال‌سازی
  • فایل hoosh-seo.php باید یک پوشه زیر ریشهٔ ZIP باشد، نه دو پوشه.
  • مطمئن شوید includes/autoloader.php هم منتقل شده است.
  • خطای واقعی در wp-content/debug.log است؛ WP_DEBUG و WP_DEBUG_LOG را موقتاً true کنید.
define( 'WP_DEBUG', true );
define( 'WP_DEBUG_LOG', true );
define( 'WP_DEBUG_DISPLAY', false );
آپلود ZIP شکست خورد یا صفحه سفید شد
  • upload_max_filesize و post_max_size را افزایش دهید.
  • اگر میزبان mod_security دارد، موقتاً غیرفعالش کنید.
  • راه‌حل همیشگی: ارسال با FTP یا wp plugin install /path/to.zip --activate.
جدول‌ها ساخته نشده‌اند
  • افزونه را یک‌بار غیرفعال و دوباره فعال کنید.
  • یا استودیو ← ابزارها ← «نصب/تعمیر جدول‌ها».
  • اگر کاربر MySQL حق CREATE ندارد، با مدیر سرور هماهنگ کنید.
نقشهٔ سایت ۴۰۴ می‌دهد

تنظیمات ← پیوندهای یکتا ← یک‌بار «ذخیره» تا قوانین بازنویسی بازسازی شود. روی NGINX:

rewrite ^/sitemap_index\.xml$        /index.php?hoosh_sitemap=index last;
rewrite ^/sitemap-([a-z0-9\-_]+)\.xml$ /index.php?hoosh_sitemap=$1  last;
توضیحات متا اعمال نمی‌شود
  • اگر قالب شما wp_head() را در footer.php صدا می‌زند، جابه‌جاش کنید؛ متا باید در <head> چاپ شود.
  • افزونهٔ سئوی دیگری را غیرفعال کنید (تداخل متا و اسکیما).
سرعت سایت بعد از فعال‌سازی کم شد

استودیو ← سرعت ← «اعمال همهٔ تیک‌های بی‌خطر» و بعد پاک کردن کش. اگر کش object (Redis/Memcached) دارید، کش افزونه را از بخش ابزارها پاک کنید.

نصب و نگهداری از خط فرمان

# نصب و فعال‌سازی
wp plugin install dist/hoosh-seo.zip --activate

# پاک کردن کش
wp cache flush

# اجرای کارهای زمان‌بندی‌شده بدون منتظر ماندن
# (کلید در استودیو ← ابزارها نشان داده می‌شود)
curl -s "https://example.com/?hoosh_cron=daily&key=KEY"
curl -s "https://example.com/?hoosh_cron=batch&key=KEY"

# زمان‌بندی واقعی با crontab
crontab -e
0 3 * * * curl -s "https://example.com/?hoosh_cron=daily&key=KEY" >/dev/null 2>&1
🕐
چرا crontab؟ wp-cron.php وردپرس فقط با بازدید صفحه اجرا می‌شود. در سایت‌های کم‌بازدید، کارهای روزانه (ردیاب رتبه، نقشهٔ سایت، ایندکس‌بان) دیر یا هرگز اجرا نمی‌شوند.

حذف کامل

برای پاک شدن همه‌چیز: استودیو ← تنظیمات ← عمومی ← گزینهٔ «حذف داده‌ها هنگام حذف افزونه» را روشن کنید، سپس افزونه را حذف کنید. اگر خاموش باشد، جدول‌ها و تنظیمات دست‌نخورده می‌مانند تا نصب دوباره همه‌چیز را برگرداند.

وقتی پیشخوان در دسترس نیست، در wp-config.php:

define( 'HOOSH_SEO_REMOVE_ON_UNINSTALL', true );
